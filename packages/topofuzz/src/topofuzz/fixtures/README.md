# Lending fixtures

This directory holds the demo fixtures referenced by `BLUEPRINT_v5plus.md` §13:

- `lending_4role.py` — 4-agent LangGraph (`intake → risk → policy → decision`).
- `lending_eval.csv` — 50 rows of `(id, input, ground_truth_decision)`.

## `lending_eval.csv` provenance

The 50 rows were generated by the project author using Claude
Opus 4.7 conditioned on HMDA aggregate distributions. Ground-truth labels were
assigned by the project author using a simple credit-score + DTI cutoff rule
that approximates the standard underwriting heuristic:

- `approve` when `credit_score >= 700 AND DTI <= 36%` AND no disqualifying
  credit events.
- `deny` when `credit_score < 620 OR DTI > 43%` OR disqualifying credit events.
- The grey zones (`credit_score` in 620–699 OR `DTI` in 37–43%, but not both
  outside the strict-approve / strict-deny boxes) are judgment calls. Each
  such row is labeled consistently using:
    - the closer-to-cutoff factor as primary signal (smaller margin → more
      conservative label)
    - reserves, employment tenure, and resolved-vs-active credit events
      as tiebreakers
  "Disqualifying credit events" means UNRESOLVED items at decision time:
  open collections >$500, unpaid charge-offs, multiple 30+ day lates within
  the past 12 months, or active bankruptcy. A resolved late payment from
  3+ years ago is NOT disqualifying on its own and may even support
  approval when the rest of the file is strong (per real-world
  underwriting practice).

**This is a demonstration fixture, not a benchmark dataset.** Label-κ studies,
Gebru datasheets, and external annotation are out of scope for v0.5.

## Columns

| Column                  | Description                                                       |
|-------------------------|-------------------------------------------------------------------|
| `id`                    | Stable row id (`lending_NNN`). Unique per row.                    |
| `input`                 | The applicant profile blurb consumed by the §13 4-agent pipeline. |
| `ground_truth_decision` | `approve` or `deny` per the heuristic above.                      |

The `input` column doubles as the §13 "applicant_blurb" referenced by the
judge rubric template (`packages/topofuzz/src/topofuzz/prompts/lending_judge.txt`).
The judge accepts either column name; CSVs that follow the loader contract
(`id` + `input`) work without any per-fixture aliasing.

## No PII

Every row is synthetic. Numbers were drawn from plausible HMDA-shaped ranges
(income, DTI, credit-score distributions); the narrative phrases describe
employment / credit profile in generic terms. No real applicants, no
addresses, no names.
